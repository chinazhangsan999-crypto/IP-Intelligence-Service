# 请求鉴权与防重放

除 `/health` 外，所有接口都必须通过应用层 HMAC 鉴权。生产环境还必须由 Cloudflare Access 使用每导航站独立的 Service Token 完成边缘准入。

## 签名步骤

1. 生成至少 16 个安全字符的随机 Nonce。
2. 生成 Unix 秒时间戳。
3. 先确定最终发送的请求体字节，不得在签名后重新格式化 JSON。
4. 对原始请求体计算 SHA-256 小写十六进制。
5. 用换行连接大写方法、原始 path-and-query、时间戳、Nonce、请求体摘要。
6. 使用该导航站密钥计算 HMAC-SHA256，输出小写十六进制。

GET 请求使用空请求体的 SHA-256。路径包含查询串时必须按实际发送顺序签名，不能先URL解码或重新排序。

## 服务端顺序

```text
限制请求体大小
  → 校验头部格式和时间窗
  → 读取客户端加密密钥
  → 常量时间比较签名
  → 检查客户端是否停用
  → 消耗Nonce
  → 执行每客户端限速
  → 进入业务接口
```

签名错误不能消耗Nonce或限速额度。通过签名后，即使请求随后被限流，其Nonce也视为已使用。

## 当前单实例边界

Nonce和分钟限速当前存放在单个Node.js进程内存中，适用于第一阶段单实例部署。启用多个中心服务实例前，必须将这两项状态迁移到共享Redis并采用原子操作，否则不同实例之间无法阻止重放。

鉴权失败、重放和限流会异步写入审计表；审计写入失败不会泄漏密钥或改变鉴权判断。成功客户端的 `last_used_at` 最多每分钟更新一次，避免每次查询都写数据库。

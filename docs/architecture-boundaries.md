# 系统边界与不变量

## 服务职责

中心 IP 系统负责：

- 规范化并查询 IPv4、IPv6 和 IPv6 `/64`。
- 返回地理、ASN、主要网络类型、独立风险标签、证据、置信度和数据库版本。
- 管理导航站客户端身份、限额、数据源版本和聚合使用量。

中心 IP 系统不负责：

- SID、友链归属、Referer、积分、入站/出站判断。
- 滑块验证、封禁、下架、反链或 Ping 巡检。
- 判断访客是否真人或是否应受处罚。
- 主动扫描访客端口、服务或漏洞。

## 数据最小化

导航站只能提交完成自身规范化后的 IP；不得提交站点名称、链接 ID、页面 URL、联系方式、Cookie、访客轨迹或访问正文。

中心服务默认不长期保存原始 IP。运行日志使用掩码或不可逆 HMAC 摘要；按客户端和小时聚合用量。错误日志不得记录密钥、完整签名或 Cloudflare Access Token。

## 业务隔离

导航站必须异步查询，并保留本地 `ip_profiles` 缓存。以下业务不能等待或依赖中心 IP 系统：

- 前台页面打开。
- 有效入站记录。
- SID 归属与友链积分。
- 总 IP、UV、PV 统计。
- 风控门禁和告警。
- 反链与连通性巡检。

中心系统超时或不可用时，导航站只显示旧缓存、`识别中` 或 `未知`，不得改变原有业务结果。

## 判断边界

- `network_type` 是主要网络归类；代理、VPN、Tor、Anycast 等使用独立三态字段。
- IP 类型第一阶段只用于后台展示和人工分析。
- 任何单一 IP 类型都不能自动封禁、扣分或触发处罚。
- 冲突证据必须保留，不能通过覆盖字段丢弃。
- 免费数据源不支持的能力必须返回 `null`，不得推断或伪造。
- 所有网络类型和三态标签必须经过统一判断引擎；数据源适配器不能直接决定最终 API 值。
- 同级、同置信度的相反证据必须回避判断并保留冲突，不允许依赖加载顺序覆盖。

## 版本原则

- `/v1` 已发布字段不得改变类型或含义。
- 可向响应增加可选字段，但客户端必须忽略未知字段。
- 删除字段、收紧枚举或改变签名原文需要发布新的 API 主版本。
- 数据库更新只改变数据结果，不改变接口语义。
